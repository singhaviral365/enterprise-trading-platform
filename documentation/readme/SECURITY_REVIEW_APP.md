# Security review: whole application

## Header

| Field | Value |
|---|---|
| Scope | The Angular frontend, auth-service, order-service, executor-service, Kafka and PostgreSQL as wired by `config/application.yml`, docker compose, and the extensions (strategies, trade signals and the AI assistant, notifications and email, portfolio and performance, preferences and currency, payload encryption) |
| Reviewed by | Team 3 |
| Date of review | 2026-10-08 |
| Commit reviewed | 9a03237, plus the uncommitted central-configuration, two-step-default, compact-amount and assistant guard-rail changes in the working tree |
| Previous review | [SECURITY_REVIEW_AUTH.md](SECURITY_REVIEW_AUTH.md), 2026-10-05, auth service only. This document covers the whole application and does not replace it: the auth-service detail (Argon2id parameters, refresh rotation, throttling, cookie attributes) stays there, and its open items are carried below |
| Version of the OWASP Top Ten used | 2021 |
| Method | Reading the code and configuration, grep for dangerous patterns, `npm audit`, and the unit tests that encode the controls. **Not done:** no running penetration test, no dynamic scan, no Java dependency scan (see A06) |

## What changed since the auth review

| Area | Before (2026-10-05) | Now |
|---|---|---|
| Payload encryption | None | JWE envelope on every auth-service body (RSA-OAEP-256 + A256GCM in, ECDH-ES + A256GCM out), bound to method, path, time and a one-time id. `optional` by default in `application.yml`, off in code until configured. Covers the auth-service only |
| Two-step sign-in | Off until a user turned it on | On for every new user; skipped (and logged) while email is off so nobody is locked out |
| Email | MailHog, development only | Three modes; a real SMTP account over TLS with certificate checks, a verified sending domain, a per-minute cap and a recipient allow-list |
| Configuration | `.env` files, hard-coded origins, ports and URLs | One git-ignored `config/application.yml`; CORS origins now come from it (this closes the auth review's hard-coded and trailing-slash origin item) |
| `npm audit --omit=dev` | auth-service 15 (1 critical); frontend 0 | auth-service **0**, frontend **0** (run 2026-10-08) |
| AI assistant | Existed, prompt rules only | Pre-model filter for take-over attempts, an `OFF_TOPIC` marker replaced by fixed wording, rate limits per platform and per account |
| Still open from the auth review | | Replay detection not wired; throttling keyed on a client-supplied header; JWT fallback literals in `app.module.ts` and `jwt.strategy.ts`; Swagger public; auth Dockerfile runs as root; no helmet or CSP |

## Categories

| Category | In scope | Finding | Disposition |
|---|---|---|---|
| A01 Broken access control | Yes | **order-service:** `ApiAuthenticationFilter` covers every `/api/v1/**` route, verifies the JWT and takes the user id from its claims only. Each module then checks that the account belongs to that user and answers `ACC-403` otherwise: preferences (`ownedAccount`), notifications (`assertAccountAccess`), strategies (`StrategyAccess`, including `requireOwned` for a strategy id), watchlists and alerts (`WatchlistAccess`), portfolio (`PortfolioAccess`), signals (`SignalAccessDeniedException`) and the trade account routes. A strategy's executor token is refused on every route except order placement. Unsigned dev tokens exist but are off (`security.dev-tokens.enabled=false`; true only in test resources). **executor-service:** `/api/v1/market/quotes` and `/candles/{symbol}` have no authentication and no rate limit by design (public market data). **Frontend:** route guards are a convenience; the server enforces. **Kafka:** no authentication, so anyone who can write to `orders` can place an order (see A04) | Mitigated for the customer-facing APIs. Residual: the market endpoints are open to anyone who can reach the port; a future route that trusts a client-supplied account id without the ownership check would reopen the gap, so each new module should reuse its `*Access` class or add one. Kafka access control is carried below |
| A02 Cryptographic failures | Yes | Passwords: Argon2id. Tokens: HS256 JWT with a shared secret (decision 0010); refresh tokens stored as SHA-256 hashes; one-time codes stored hashed and compared in constant time. Cookies: HttpOnly, SameSite=Strict, refresh scoped to `/auth`; `Secure` only in production. **Transport:** none of the services terminate TLS themselves; HTTPS has to come from the deployment, and over plain http the cookies and every order-service body travel in clear text. **Payload envelope** covers the auth-service only; order and executor bodies are plain JSON. **Email:** TLS 1.2+ with certificate and host-name checks, no setting turns that off; credentials come only from `application.yml`. **At rest:** `config/application.yml` holds the JWT secret, database passwords, API keys, the SMTP app password and the RSA private key in plain text; it is git-ignored. **Kafka and PostgreSQL** connections are plaintext. The JWT fallback literals remain in the auth-service (`app.module.ts`, `jwt.strategy.ts`) | Accepted for local development. **Before any shared or public deployment:** serve HTTPS and set `auth.cookie.secure`, move secrets to a secret store, enable TLS on Postgres and Kafka, extend the envelope to the other services or rely on TLS, and remove the fallback literals. The envelope is defence in depth and must not be used as a reason to relax any of these |
| A03 Injection | Yes | **SQL:** MyBatis mappers use `#{}` only; a search of every mapper for `${` finds it only in comments that say it is not used. The auth-service uses TypeORM repository calls; its only raw SQL is static. **Command and template injection:** none found. **XSS:** the Angular templates contain no `innerHTML`, `outerHTML`, `bypassSecurityTrust*`, `document.write` or `eval`; the assistant's reply is shown as text. **Header injection:** email subjects are flattened to one line. **Path and symbol input:** the market candles route validates the symbol (`[A-Za-z0-9.\-_:^=]{1,32}`) and URL-encodes it into the upstream path; the signals route bounds it to 20 characters. **Prompt injection:** the customer's words are always a user turn, never part of the instructions; take-over phrases are refused before the model is called, and the model is told to answer off-topic with a marker the service replaces. It has no tools and only the signal's numbers and units held | Finding of none for SQL and XSS. Residual: the take-over filter is a deny-list and some phrasings will pass; the model's own refusal and the reply cap (1,200 characters, control characters stripped) are the second line |
| A04 Insecure design | Yes | **Strengths:** an order is placed only through `POST /api/v1/orders` (idempotency key, validation, account checks); strategies cannot write orders or publish to `orders` and a test fails the build if they do; strategy limits are derived and checked again at placement; events are published only after the database commit; one-time codes are limited by attempts, sends and a cooldown; the assistant has rate limits. **Weaknesses:** (1) no rate limiting on the order, portfolio or market routes, so a signed-in customer or anyone reaching the market port can generate load and upstream calls; (2) the executor's per-symbol candle cache is an unbounded map, so an unauthenticated caller can grow it with many valid symbols and cause one upstream call each; (3) the executor trusts the content of `orders` messages, so Kafka access equals the ability to place orders; (4) auth-service replay detection is still not wired and login throttling is keyed on `X-Forwarded-For` (carried from the auth review); (5) access tokens cannot be revoked (15 minutes) | Accepted with the follow-ups below. (1) and (2) are the cheapest to fix and the most exposed |
| A05 Security misconfiguration | Yes | **No security headers and no Content-Security-Policy anywhere** (frontend, auth, order, executor). **Debug logging (fixed 2026-10-08):** `org.mybatis` and `org.springframework.jdbc` were at DEBUG in both Spring services' main properties, so in every profile each statement and its bound values were logged, which includes personal data. They are now WARN. **Auth-service:** Swagger and `/api-docs-json` are public; the Dockerfile has no `USER`, so it runs as root (the order-service Dockerfile does set `USER app`; the executor has none). **Executor:** `/api/v1/market` is open (A01). **Actuator:** only `health` is exposed, plus `metrics` in the `dev` profile. **CORS:** order and executor send none (same-origin through the proxy); the auth-service allows the frontend origin from `application.yml` with credentials. **Repository hygiene:** `services/executor-service` has run and test logs committed (`*.log`, `run-logs/`); a check for passwords, keys and tokens found only Kafka client settings printed as `null`, but logs should not be in git. **Secrets:** `config/application.yml` is git-ignored and was never committed; IDE workspace files that hold local credentials are not tracked | Accepted. Highest value fixes: add helmet and a CSP, drop the committed logs, serve Swagger only outside production, run the containers as non-root |
| A06 Vulnerable and outdated components | Yes | `npm audit --omit=dev` on 2026-10-08: auth-service 0, frontend 0 (the auth-service fixes are the overrides and upgrades in its `package.json`). **Java:** no dependency scan was run for the order and executor services (Spring Boot 4.1.1, Kafka clients 4.2.1, MyBatis) because no scanner is configured in the build. The frontend loads Font Awesome from cdnjs | **Gap.** Add the OWASP Dependency-Check or an equivalent to the Maven build and record its result; until then the Java components are unreviewed for known CVEs |
| A07 Identification and authentication failures | Yes | Argon2id; uniform `AUTH-401` for unknown user and wrong password; password rules in the DTO and the UI; one-time codes (6 digits, hashed, 5 guesses, 300 s, resend cooldown and cap); **two-step sign-in on by default**, skipped while email is off; sessions as HttpOnly cookies with single-flight renewal; logout revokes the refresh token; registration verifies the email address with a code. Weaknesses carried from the auth review: throttling bypassable by rotating `X-Forwarded-For`, no per-account lockout, registration reveals whether a name or email exists (`AUTH-409`) | Mitigated. Skipping the second step while email is off is a deliberate fail-open (a lock-out was judged worse) and must not be the state of a real deployment |
| A08 Software and data integrity failures | Yes | **Kafka consumers read plain strings and parse them into typed objects themselves**, so there is no polymorphic deserialization of attacker-chosen classes. Lock files (`package-lock.json`) are present; the generated API clients are checked against the contracts by `npm run api:check`. **Gaps:** Font Awesome is loaded from a CDN stylesheet with no Subresource Integrity attribute, so a compromised CDN could restyle or hide parts of the page; there is no build signing and no check of the Java dependency checksums beyond Maven's defaults; messages on `orders` are unsigned | Accepted. Add SRI (or self-host the icon font) and decide whether messages need signing before Kafka is shared |
| A09 Security logging and monitoring failures | Yes | Auth-service: a redacting logger removes passwords, tokens and authorisation values; failures, refreshes and logouts emit events. Order-service: warnings for a cookie-authenticated change without the CSRF header, for a strategy token used outside order placement, and for refused addresses; email logs carry delivery ids and reasons, never addresses or text. Metrics for the assistant (`signals.gemini.calls` by outcome, tokens, latency) at `/actuator/metrics` in the `dev` profile. The assistant logs one start-up line saying whether Gemini is configured, never the key. **Gaps:** no central collection or alerting; throttle blocks and replay attempts are not distinct events; the SQL debug logging that put personal data into logs has been switched off (A05) | Partly mitigated. Redaction is good where it exists; visibility across services is thin |
| A10 Server-side request forgery | Yes | Every outbound address comes from `application.yml` (Fauxnance, ExchangeRate-API, Gemini, the SMTP host). The only request values that reach a URL are instrument symbols, which are validated and URL-encoded, and numeric ids. No endpoint fetches a URL a user supplies; the Gemini base URL and model are configuration, not input | Finding of none. A change that lets a caller choose a host (a webhook, an import by URL) needs an allow-list first |

## Evidence

| Check | How it was performed | Result |
|---|---|---|
| Authentication filter and ownership checks | Read `ApiAuthenticationFilter`, the `*Access` classes and the service methods that call them (preferences, notifications, strategies, watchlist, portfolio, signals) | Claims-only identity; `ACC-403` on a foreign account; executor token limited to order placement |
| SQL injection | Searched `order-service` and `executor-service` mappers for `${`; read the auth-service data access | Only comments mention it; bound parameters elsewhere |
| XSS | Searched the frontend for `innerHTML`, `outerHTML`, `bypassSecurityTrust`, `document.write`, `eval(` | None in application code |
| Browser storage | Searched for `localStorage`, `sessionStorage`, `document.cookie` | Username and expiry, and the theme only |
| Public surface | Read `MarketController`, `PriceHistoryService` | Open, symbol validated, cache keyed by symbol with no bound |
| Debug logging | Read both Spring services' `application.properties` | MyBatis and JDBC were at DEBUG in every profile; now WARN |
| Containers | Read the auth and order Dockerfiles; looked for one in the executor | Auth root; order `USER app`; no executor Dockerfile |
| Components | `npm audit --omit=dev` in `frontend` and `services/auth-service` | 0 and 0 |
| Kafka input | Read the consumer configuration | String deserializers; messages parsed into typed records |
| Outbound requests | Read the clients and `application.properties` | Hosts from configuration only |
| Encryption | Read `src/encryption/*`, `core/encryption/*`; the unit tests exercise real HTTP round trips, tampering, replay, expiry, wrong key and wrong path | Behaves as specified; covers the auth-service only |
| Assistant guard rails | Read `GeminiSignalExplainer`; its tests cover take-over phrases, the marker and an ordinary question | Fixed wording for refusals; the model is not called for take-over attempts |
| Repository hygiene | `git ls-files` for logs; a pattern search of them | Logs are tracked in `services/executor-service`; no credentials found in them |
