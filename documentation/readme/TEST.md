# Testing

Test and coverage guide for this repository. Backend (Java, Linux) first, then Frontend (Angular) and end-to-end.

## Backend

Test report guide (Linux). Run from backend folder.
Run from backend folder.

### Prerequisites

Use Maven Wrapper from this repo (no system Maven required):

```bash
chmod +x mvnw
./mvnw -v
```

If Java is missing, install JDK 21 first (example for Amazon Linux):

```bash
sudo dnf install -y java-21-amazon-corretto-devel || sudo yum install -y java-21-amazon-corretto-devel
java -version
```

### Install required snapshot dependency (required)

The backend tests depend on `com.enterprise.trading:sprint-05-domain-engine:1.0-SNAPSHOT`.
Install it into your local Maven repository before running tests.

Run from repository root:

```bash
export CORE_JAVA_REPO_URL="$(git config --get remote.origin.url)"
export CORE_JAVA_REF=core-java

rm -rf /tmp/core-java-dep
git clone --depth 1 --branch "$CORE_JAVA_REF" "$CORE_JAVA_REPO_URL" /tmp/core-java-dep
./backend/mvnw -B -f /tmp/core-java-dep/backend/pom.xml -DskipTests install
```

Quick verification:

```bash
ls ~/.m2/repository/com/enterprise/trading/sprint-05-domain-engine/1.0-SNAPSHOT
```

### Run tests

```bash
cd backend
./mvnw -B clean test
```

Note:
- A warning about missing `/home/<user>/.docker/config.json` or `DOCKER_AUTH_CONFIG` during Testcontainers startup is expected when you are not using a private registry.
- It is informational and can be ignored for public images like `postgres:16-alpine` and `testcontainers/ryuk`.

### Generate Surefire report

```bash
./mvnw -B surefire-report:report
```

Report outputs:
- XML results: backend/target/surefire-reports
- HTML report: backend/target/reports/surefire-report.html

### Open report locally on Linux

```bash
xdg-open target/reports/surefire-report.html 2>/dev/null || echo "Open target/reports/surefire-report.html manually"
```

### Export report into versioned folder for GitHub

Run from repository root.

```bash
rm -rf reports/surefire/backend-tests-report
mkdir -p reports/surefire
cp -r backend/target/reports reports/surefire/backend-tests-report
cp -r backend/target/surefire-reports reports/surefire/
```

This preserves all report assets (css, fonts, images, img, js) so status icons and styling render correctly.

### Commit and push report

```bash
git add reports/surefire
git commit -m "Add surefire test report"
git push
```

Optional quick summary from XML files:

```bash
grep -R "tests=\|failures=\|errors=\|skipped=" backend/target/surefire-reports/*.xml
```

## Frontend

All commands run from the `frontend` folder.
Unit tests run on **Vitest** (the Angular CLI's `unit-test` builder) in jsdom. Coverage is measured with
**Istanbul**. Both reports are generated by the tools, never hand-written.

### One-time install

```bash
cd frontend
npm install        # picks up @vitest/coverage-istanbul and @vitest/ui from package.json
```

(They were added with `npm install -D @vitest/coverage-istanbul @vitest/ui`.)

### Commands

| Command | What it does |
| --- | --- |
| `npm test` | Watch mode, no coverage. Use while developing. |
| `npm run test:ci` | One run **with coverage**; writes both reports below and fails if coverage drops under the thresholds. |
| `npm run test:report` | Serves the HTML test report (`test-reports/html`). |
| `npm run coverage:report` | Serves the HTML coverage report (`coverage/frontend`). |
| `npx ng test --watch=false --include='src/app/core/**/*.spec.ts'` | Run a subset. |

### Where the output goes

| Output | Path | Contents |
| --- | --- | --- |
| Test report (HTML) | `test-reports/html/index.html` | Every suite and test, pass/fail, durations |
| Test report (JUnit XML) | `test-reports/junit.xml` | Same results for CI dashboards |
| Coverage (HTML) | `coverage/frontend/index.html` | Per-file, line-by-line drill-down |
| Coverage (LCOV) | `coverage/frontend/lcov.info` | For Sonar and other tools (see [SONARQUBE.md](SONARQUBE.md)) |
| Coverage (JSON summary) | `coverage/frontend/coverage-summary.json` | Totals, machine-readable |

Both folders are git-ignored.

* **Coverage HTML** is static: double-click `coverage/frontend/index.html`.
* **Test report HTML** is a single-page app that loads its results with `fetch()`, which browsers block on `file://`, so double-clicking shows a blank page. Serve it with `npm run test:report` (opens http://localhost:4173). Use `test-reports/junit.xml` when you need a file that opens anywhere.

### Coverage rules (angular.json -> test -> options)

* Measured: `src/app/**/*.ts`.
* Excluded: `src/app/api/generated/**`, `src/app/showcase/**`, `src/app/testing/**`, `src/test-setup.ts`, specs.
* Thresholds (the run fails below them): statements 90, branches 85, functions 85, lines 90.

#### Why the generated API clients are not tested

`src/app/api/generated/**` is output of OpenAPI Generator, committed on purpose and never edited by hand.
Unit-testing it would test the generator, not our code, and inflate the percentage. Coverage of it is instead
guaranteed two other ways:

1. `npm run api:check` regenerates the clients and fails if they differ from what is committed (contract drift).
2. The hand-written wrappers `AuthApi` and `TradeApi` are tested against the contract paths, methods and
   bodies (`api/*.spec.ts`), so every call the app makes goes through the generated code under test.

#### Why Vitest and not Karma

The CLI offers a `karma` runner, but this project's specs use Vitest APIs (`vi.waitFor`, `vi.fn`,
`vi.useFakeTimers`), and Karma needs a real Chrome. Switching would mean rewriting every spec. Istanbul coverage,
the HTML report and the JUnit report all work with Vitest, so nothing the Karma stack would have given is missing.

### Writing specs

* `src/test-setup.ts` runs before every file: it polyfills `<dialog>.showModal()` for jsdom and clears
  `localStorage` before each test (a leftover session makes stores fire account requests nobody answers, and
  `fixture.whenStable()` then never resolves).
* `src/app/testing/trade-http.ts` has the shared helpers: sample quotes, order entries and
  `answerLinkedAccount(http)` for the link lookup plus the four account reads.
* When a component fires HTTP, flush every request before `await fixture.whenStable()`; it waits on them.
